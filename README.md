## Overview

This repository contains two projects that explore the same core idea from different directions: LLMs can act as data generators and query authors when they are given a well-structured prompt.

| Project | Objective | Core techniques |
| --- | --- | --- |
| **Project 1** | Generate one fact table and two dimension tables (plus two distractor tables) from a natural-language specification | Prompt engineering, Doubao API integration, extraction and execution of generated Python code, DataFrame-to-Excel export |
| **Project 2** | Split a wide Excel table into two subtables, then generate and verify analytical SQL | Prompt templates, ASCII serialization of tables, regex-based code extraction, SQL review and correction |

Both projects follow the same pipeline:

1. Serialize the task and any tabular input into a prompt.
2. Call the LLM through an API.
3. Extract the relevant code from the response.
4. Execute the code and persist the result.

## Project 1: Table Generation from a Natural-Language Specification

### 1.1 Goal

Given a natural-language specification, the LLM must produce five tables:

- One **fact table** (`Events`) with a primary key and foreign keys referencing the two dimension tables.
- Two **dimension tables** (`Campaigns` and `Users`).
- Two additional **distractor tables** that are plausible but irrelevant to the campaign-performance analysis.

The three core tables must be joinable, contain realistic data, and ship with MySQL-compatible `CREATE TABLE` statements.

### 1.2 Environment Setup

1. Open the Volcengine console at <https://console.volcengine.com/>.
2. Locate the `Doubao-Seed-1.6-vision 250815` model required by the assignment and enable API access.
3. Complete identity verification to obtain an **API key**.
4. Copy the generated Python invocation snippet into the project and configure the key.

### 1.3 Prompt Design

The prompt is built around four principles:

- **Assign a clear role and task.** The model is told that it is an experienced data analyst skilled in SQL and Python, and exactly how many tables to generate.
- **Provide the business context and an explicit schema.** The background explains how the three tables are used, and every column is listed with its type, key constraints, and meaning.
- **State the requirements as a numbered checklist.** Row count, joinability, DDL output, and distractor tables are all specified explicitly.
- **Include a worked example.** A small sample of each table shows the expected shape and value conventions, reducing output variance.

### 1.6 Generation Pipeline

The structured prompt is embedded in Python and sent to the LLM. The returned code is then executed to build the tables.

```python
# 1. Load the prompt
input = readFile(file_path)

# 2. Ask the LLM for a response (through the API)
output = extract_doubao_response(callLLM(client, model, input))

table_path = "Table"

# 3. Execute the Python code in the response to build DataFrames
df_dict = extract_and_execute_llm_python_code(output)

# 4. Convert the DataFrames to xlsx and save them to the target path
save_dataframes_to_xlsx(df_dict)
```

The resulting workbook is saved as `Project01/Table/ad_analysis_tables.xlsx`.

> **Note:** The pipeline executes Python code returned by the model. Only run it with trusted prompts and in an environment you control.

### 1.7 Lessons Learned

The main difficulty was processing the LLM response, specifically:

1. **Extracting only the needed content** from a response that mixes explanation, code, and commentary.
2. **Writing prompts that reduce redundant output** — verbose responses make regex-based extraction more expensive and less reliable.
3. **Keeping responses consistent** across repeated calls, so that the same parsing logic continues to work.

## Project 2: Table Splitting and SQL Generation

### 2.1 Goal

Starting from a wide `HR_Analytics.xlsx` table, the pipeline:

1. Asks the LLM to split the wide table into two normalized subtables.
2. Sends those subtables back to the LLM with an analytical query.
3. Extracts the generated SQL and verifies its correctness.

### 2.2 Splitting the Wide Table

The wide table is embedded in a prompt template and the LLM returns Python code that constructs the two subtables.

#    The prompt is a template; the wide table is represented by a
#    {dataframe_content} placeholder.

#    ASCII table, and substitute it into the template.

# Load the prompt-template file into a variable
def readFile(file_path)

# Read the xlsx file into a DataFrame

# Convert a DataFrame to an ASCII table
def df_to_ascii(df)

# Merge the prompt template with the ASCII table
full_prompt = prompt_template.format(dataframe_content=df_str)

The subtables are passed back to the LLM together with a query template so that the model can author the SQL.

### 2.4 Validating the Generated SQL

**Requirement.** Using the provided table, count male employees, female employees, married employees, and single employees; count employees at each education level; compute the maximum and minimum commute distance; compute the average total years of work experience and the average years at the company — grouped by age group in ascending order, and restricted to employees who have been with the company for at least two years.

**SQL generated by the LLM:**

```sql
SELECT `年龄组`,
       SUM(CASE WHEN `性别` = 'Male' THEN 1 ELSE 0 END) AS 男员工数量,
       SUM(CASE WHEN `性别` = 'Female' THEN 1 ELSE 0 END) AS 女员工数量,
       SUM(CASE WHEN `婚姻状况` = 'Married' THEN 1 ELSE 0 END) AS 结婚员工数量,
       SUM(CASE WHEN `婚姻状况` = 'Single' THEN 1 ELSE 0 END) AS 未婚员工数量,
       SUM(CASE WHEN `教育程度` = 1 THEN 1 ELSE 0 END) AS 教育程度1人数,
       SUM(CASE WHEN `教育程度` = 2 THEN 1 ELSE 0 END) AS 教育程度2人数,
       SUM(CASE WHEN `教育程度` = 3 THEN 1 ELSE 0 END) AS 教育程度3人数,
       SUM(CASE WHEN `教育程度` = 4 THEN 1 ELSE 0 END) AS 教育程度4人数,
       SUM(CASE WHEN `教育程度` = 5 THEN 1 ELSE 0 END) AS 教育程度5人数,
       MAX(`通勤距离`) AS 最远通勤距离,
       MIN(`通勤距离`) AS 最近通勤距离,
       AVG(`总工作年限`) AS 平均总工作年限,
       AVG(`在本公司工作年限`) AS 平均本公司工作年限
FROM employees
WHERE `在本公司工作年限` >= 2
GROUP BY `年龄组`
ORDER BY `年龄组` ASC;
```

**Review.** The statement is essentially correct and covers every requested field. However, `年龄组` (age group) is stored as a string, so sorting directly on it is not semantically sound: lexicographic order does not necessarily match numeric age order. The revised version extracts the starting age from the label and sorts on that numeric value.

**Revised SQL:**

```sql
WITH TEMP1 AS (
    SELECT `员工ID`,
           `年龄`,
           `年龄组`,
           `性别`,
           `婚姻状况`,
           `教育程度`,
           `教育领域`,
           `通勤距离`,
           `总工作年限`,
           `在本公司工作年限`,
           SUBSTRING_INDEX(`年龄组`, '-', 1) AS 起始年龄
    FROM employees
)
SELECT `年龄组`,
       `起始年龄`,
       `男员工数量`,
       `女员工数量`,
       `结婚员工数量`,
       `未婚员工数量`,
       `教育程度1人数`,
       `教育程度2人数`,
       `教育程度3人数`,
       `教育程度4人数`,
       `教育程度5人数`,
       `最远通勤距离`,
       `最近通勤距离`,
       `平均总工作年限`,
       `平均本公司工作年限`
FROM (
    SELECT `年龄组`,
           MAX(`起始年龄`) AS 起始年龄,
           SUM(CASE WHEN `性别` = 'Male' THEN 1 ELSE 0 END) AS 男员工数量,
           SUM(CASE WHEN `性别` = 'Female' THEN 1 ELSE 0 END) AS 女员工数量,
           SUM(CASE WHEN `婚姻状况` = 'Married' THEN 1 ELSE 0 END) AS 结婚员工数量,
           SUM(CASE WHEN `婚姻状况` = 'Single' THEN 1 ELSE 0 END) AS 未婚员工数量,
           SUM(CASE WHEN `教育程度` = 1 THEN 1 ELSE 0 END) AS 教育程度1人数,
           SUM(CASE WHEN `教育程度` = 2 THEN 1 ELSE 0 END) AS 教育程度2人数,
           SUM(CASE WHEN `教育程度` = 3 THEN 1 ELSE 0 END) AS 教育程度3人数,
           SUM(CASE WHEN `教育程度` = 4 THEN 1 ELSE 0 END) AS 教育程度4人数,
           SUM(CASE WHEN `教育程度` = 5 THEN 1 ELSE 0 END) AS 教育程度5人数,
           MAX(`通勤距离`) AS 最远通勤距离,
           MIN(`通勤距离`) AS 最近通勤距离,
           AVG(`总工作年限`) AS 平均总工作年限,
           AVG(`在本公司工作年限`) AS 平均本公司工作年限
    FROM TEMP1
    WHERE `在本公司工作年限` >= 2
    GROUP BY `年龄组`
    ORDER BY `起始年龄` ASC
) AS TEMP2;
```

### 2.5 Query Prompt Design

The query prompt is deliberately detailed. It contains:

- A **background** section describing the data and the analytical goal.
- A list of **query requirements**, presented as bullet points.
- A **concrete example** that includes both the analysis process and the complete SQL.

Like the splitting prompt, the query prompt uses placeholders. This keeps the template flexible and provides a clean way to inject the subtables into the prompt.

### 2.6 Passing Tables to the LLM

The projects pass tabular data to the model in three steps:

1. Read the `.xlsx` or `.csv` file into a pandas `DataFrame`.
2. Convert the `DataFrame` to an ASCII table.
3. Insert the ASCII table at the placeholder in the prompt template.

After these three steps, the table and the textual prompt are sent to the LLM as a single request.

**Alternative approach:** Represent the table as a `DataFrame` in Python first, then send the corresponding `DataFrame` construction code to the LLM instead of an ASCII rendering.

## Summary

Both projects share a reusable pattern for LLM-assisted data work:

1. **Describe** the task, schema, and constraints precisely in a prompt.
2. **Serialize** any input table into a representation the model can read — ASCII tables or `DataFrame` code.
3. **Generate** Python or SQL with the model.
4. **Extract and validate** the generated artifact before using it.

The recurring engineering challenge is not the model call itself, but controlling the response format so that the generated code can be extracted reliably and executed safely.
